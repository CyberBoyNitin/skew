Method

01
generate

A seeded grammar emits extraction probes around JSON edge cases, and custom probe files can add tool-use and safety cases.

02
sample

Every stack answers every probe N times at temperature 0. Calls are retried with backoff and bounded by a concurrency limit. With a multi-turn config, tool calls are answered from static, argument-routed, or sequenced results and the model continues until it stops or hits the turn budget. Routes can branch on call arguments, and steps can return a result or inject an error to exercise retry paths.

03
classify

Stacks that disagree with themselves are marked unstable. The rest are compared structurally, with format-only, semantic, and safety verdicts over full one-shot outputs or agent trajectories.

04
minimize

Each divergence is delta-debugged over prompt segments and re-verified at the full trial count. Only reductions that reproduce the same disagreement are kept.

Limits read before acting on a finding

  1. Stability is estimated from 3 trials. Temperature 0 reduces noise but does not remove it; stacks below the 0.8 threshold are reported as unstable, never as findings.
  2. Minimization uses one trial per stack because the search is call-heavy. Every reduced prompt is re-checked at the full trial count; if it no longer reproduces, the original prompt is kept and the finding is marked unverified.
  3. Prompts are minimized by removing whole segments (lines and blocks). The minimizer does not rewrite or paraphrase text. Scripted follow-up user turns are fixed during minimization.
  4. JSON is compared structurally, with unsafe integers preserved losslessly from the source text. Prose is compared after whitespace normalization.
  5. Native tool calls are normalized to {name, arguments}. Provider ids, envelopes, and serialization differences are ignored; tool choice and argument values are compared.
  6. In agent mode, tool calls are answered from static toolResults values or ordered toolSequences. skew never executes a tool or performs a real side effect. Each sequence step is a result or an injected error; after the last step, the last step repeats. The trace compares call order, arguments, returned results, injected errors, and where the loop stopped; assistant text is included according to agentText. The default final omits pre-tool narration because it is high-variance. Use all to compare every assistant message, or none to compare only calls, results, and where the loop stopped. Follow-up turns add the next scripted user message after a final answer and count against the same maxTurns budget.
  7. Probes can override global toolResults, toolSequences, and toolRoutes tool by tool. An override replaces the global entry for that tool, so one suite can exercise different retry, failure, and recovery paths without shared sequence state. A probe cannot define more than one of a static result, a sequence, and a route list for the same tool.
  8. Argument-aware routes match a subset of tool-call arguments recursively; extra argument keys are allowed. The first matching route wins, and a route without when is a fallback and must be last. A call with no matching route receives an injected no_matching_tool_route error. Sequences inside routes advance per route, not per tool, so two entities can have independent state.
  9. Stacks speak either OpenAI chat-completions or the Anthropic Messages API. Provider-specific sampling controls are not compared.
